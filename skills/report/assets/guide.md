# report の構成ガイド

## 構成

読み手が迷わず次の行動に移れる順にする。

1. 冒頭に結論と、読者に取ってほしい行動。状態バッジ (完了 / 進行中 / 未着手) を添える
2. 決定があれば「決まったこと」。未決 (「決めてほしいこと」) と分ける
3. 目次。見出しには安定した id (英語の kebab-case) を付け、crit の往復で変えない
4. 「前提と制約」。推定した前提と、コメントで訂正された前提をここに集める
5. 型ごとの必須セクション (下表)
6. 末尾に「次の一手」。読者が 2 分以内に取れる行動を 1 つ書く
7. 数字を載せた時は、末尾に集計方法や出典を小さく添える
8. 最後に作成日と、作成に使った生成 AI のモデル名 (例: Claude Fable 5.1) を書く

## 型

調査レポート / 比較・提案 / 解説 の 3 型と、どれにも合わない「その他」。

| 型 | 必須セクション | 生成前に聞くこと | 既定の図表 |
|---|---|---|---|
| 調査レポート | 結論 / 全体像 / 各論 / 比較と使い分け / 出典 | 読者の前提知識 / 範囲と深さ / 比較対象を置くか / 出典をどこまで載せるか | 比較表、事実カード (数値) |
| 比較・提案 | 結論と推奨 / 前提と制約 / 案 A〜C (画面イメージ) / 比較表 (既存手段との差を含む) / ボツ案と理由 / 決めてほしいこと | 決める人 / 評価軸 (コスト、工数、リスク、効果) / 譲れない制約 / 案の数と画面イメージの要否 | 案ごとのワイヤー、◎○△ 表 |
| 解説 | 結論 / 仕組みの図 / 変更点 (diff があれば) / 試し方 | 読者の前提知識 / 深さ (使い方まで、仕組みまで) / diff やコードを載せるか / 試し方が要るか | フロー図、コード抜粋 |
| その他 | 結論 / 内容に合わせた節 / 次の一手 | 何を伝えたい・決めたいか / 読者と目的 (承認を取る、共有だけ、crit 上で回答してもらう) / 必要な節 / 図表の要否 | 内容に合わせる |

3 型のどれにも合わなければ「その他」にし、必要な節は生成前の質問と依頼文から目的に合わせて組む (例: 作業の進捗を報告するなら「状態 / やったこと / お願いしたいこと」、crit 上で答えてもらうなら「番号付きの質問 (推奨と選択肢付き) / 回答欄の目印」)。図解つき / プロコン / 複数案 / 他者向けは型ではなく、どの型にも付けられる指示として扱う。既存 HTML への追記は型を引き継ぐ。

## 文章

1. 前置き、締めの挨拶、自己言及 (「本レポートでは」) を書かない
2. 手順や決めてほしいことは番号付きで、1 項目 1 行動 (または 1 判断)
3. 1 文 30〜45 字、読点 0〜2 個を目安にする
4. 意味を変えない。会話に無かった情報を足さない
5. 比喩動詞 (効く、壊れる、倒す、潰す、刺さる) を具体的な動詞に直し、擬人化 (「ツールが考える」) を避ける
6. 英語直訳の構文 (「X ではなく Y」の修辞、「〜することができる」) を直す
7. 常体・敬体は読者から決め、文書内で混ぜない
8. 装飾記号 (絵文字、文末コロン、ダッシュ) を使わない。太字は 1 段落 1 箇所まで
9. 数字には根拠 (出典、集計方法) を添える
10. 見出しだけで流れが追えるか確かめる

## 図と表

- 図は「読者に何を分からせたいか」を 1 つに絞る。流れの向き、強調の対象、ラベルの粒度を揃える
- 図は inline SVG。箱の幅は「文字数 × フォントサイズ + 24px」を下限にし、文字を折り返さない。全体は viewBox で縮める
- 表は 6 列まで。超えたらカードに分ける
- 図表を追加・変更した時は 1280px と 390px のスクリーンショットで、文字被り・はみ出し・横スクロールと、意図が伝わるかを確認する

## ページ

- self-contained。CDN・外部フォント・外部スクリプトを使わず、CSS はインラインで書く
- ダーク基調で作る。ライト対応や切替は不要。配色は `:root` のトークンにまとめる
- 左右 16px の余白。横スクロールを出さず、390px 幅でも崩さない
